5. EFFECTIVE sshd CONFIG
--------------------------------------------------------------------------------
$ docker exec cg-bastion /usr/sbin/sshd -T -f /etc/ssh/sshd_config
exit 0, 83 lines; selected effective values:

  maxauthtries 3
  maxsessions 4
  permitrootlogin no
  pubkeyauthentication yes
  passwordauthentication no
  allowtcpforwarding yes
  forcecommand /usr/local/bin/session-audit
  loglevel VERBOSE
  authorizedkeysfile /run/authorized_keys/%u
  allowusers bastion
  permitopen *:22

Two Alpine-unsupported Debian directives found during the first start
(UsePAM, PrintLastLog) were removed; startup is now clean.

The entrypoint stages authorized keys from the read-only host mount into tmpfs
as root:root 0644. This is required for StrictModes on Windows bind mounts and
for sshd's privilege-separated child to read the public keys. Key changes need
a container restart.

7. TCP FORWARDING PATH
--------------------------------------------------------------------------------
$ ssh ... -W 127.0.0.1:22 bastion@127.0.0.1
channel 0: open failed: connect failed: Connection refused
stdio forwarding failed
exit 255

The forwarding channel was accepted and sshd attempted the target connection;
the test container had no listener on port 22, so the connect was refused.
This is not claimed as an end-to-end proxy test. `PermitOpen *:22` is the
configured destination restriction; a real private target is required to
complete the proof in the live stage.
